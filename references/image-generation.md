# 按需调用本地生图技能

用于 PPT 创作中需要插画、情境画面、视觉隐喻或氛围背景的页面。配图可以帮助解释内容、建立气氛和丰富页面；按页面需要选择，不固定配图比例，也不要求每页都有图片。

## 发现当前可用能力

1. 先查看当前 agent 环境提供的已安装技能清单；环境提供技能发现工具时，可查询“图片生成 / 生图 / 插画生成”等能力。
2. 读取匹配技能的 `SKILL.md` 或使用说明，确认它能生成图片、相关工具在当前会话可调用，并按该技能的流程执行。名称如 `imagegen` 只是线索，不硬编码某个技能名、安装路径、模型、API 或调用命令。
3. 确认可用后，在用户的 PPT 创作范围内主动选择适合配图的页面，无需用户另外逐页提出“请生图”。用户指定的配图方式、参考素材和不使用生成图的要求优先。
4. 没有可调用能力时继续用原生形状、图表、现有素材完成制作。缺少可选技能不阻断交付，也不自动安装插件、配置接口或索要密钥。

技能发现由 agent 完成，不能靠 Node 脚本扫描文件名或安装 npm 包来代替；`doctor` 只检查编译运行环境。

## 在页面计划中选择用途

适合配图的情况包括：

| 页面需要 | 可生成的局部素材 | 与页面配合 |
| --- | --- | --- |
| 封面或章节页建立主题气氛 | 编辑式插画、抽象场景、背景纹理 | 按标题位置预留留白，标题另用原生文字 |
| 解释应用场景或工作方式 | 场景示意、产品概念图、局部剖面插画 | 用原生标签和连线解释关键点 |
| 表达增长、协作、韧性等抽象概念 | 桥梁、连接、生态等视觉隐喻 | 让图呼应本页结论和整体风格 |
| 一段内容需要图文节奏 | 与内容相关的人物、环境或物体插画 | 配合现有图文版式或自由构图 |

先明确图片承担的作用和占据的区域，再写生成描述。数据密集的图表或表格页通常优先保证信息清晰；需要配图时给它明确的局部位置。

图片生成的是说明性视觉，不是事实证据。介绍真实产品、人物、建筑或现场时，优先保留用户提供的真实素材；生成概念图时在备注说明其示意性质。

## 把整套视觉语言交给生图技能

提示词描述以下信息即可，不必给所有图片套同一构图：

- **内容与用途**：本页表达的主题，图片中出现什么，作为背景、插画还是独立物体。
- **共享风格**：主题色、画风、材质、光线和细节密度；同一套稿件复用这些描述。
- **构图与尺寸**：图片区域的宽高比、主体朝向和位置、需要给原生文字或图表留白的区域。
- **文字分离**：请求 `no text, no letters, no numbers, no watermark`；标题、正文、数字和图表标签由 PPT 原生对象绘制。
- **背景**：独立物体或贴纸式插画可在技能支持时请求透明 PNG；情境画面和整页背景按设计选择普通背景。

例如，某页右侧需要工业协作示意图时：

> Editorial illustration of modular robotic arms working together, restrained navy and orange palette, soft studio lighting, main subjects on the right, generous clean space on the left, landscape composition, no text, no letters, no numbers, no watermark.

这是内容和风格示例，不绑定具体图片服务。需要参考图或编辑既有素材时，按所选生图技能的输入和引用方式提供材料。

## 生成后作为普通图片落地

1. 等待生图技能实际返回可用图片，再引用资源。仅有生成提示、任务编号或尚未完成的任务不算图片。
2. 按该技能的保存方式，把实际图片放到 deck 项目的既有资源目录，平铺命名，如 `slide-04-illustration.png`。不要把用户素材写入技能安装目录；临时输出需落实为后续仍可访问的项目资源。
3. DSL 使用真实的本地 `path` 或内嵌 `data`；本地路径相对 deck 文件解析。例如：

   ```json
   {
     "elType": "image",
     "id": "slide-04-illustration",
     "path": "images/slide-04-illustration.png",
     "x": 770, "y": 170, "width": 430, "height": 430,
     "sizing": { "type": "contain" }
   }
   ```

   此例要求 deck 旁已有 `images/slide-04-illustration.png`。按图片在页面上的实际角色选择 `contain` 或 `cover`；WebSlide 使用真实图片资源并标记 `data-ppt="image"`，见 [WebSlide 协议](webslide.md)。
4. 图片放在对应文字和标注之前，保留需要的留白与对比度。文字、数字、图表、表格及主要关系继续用原生对象，不让一张生成图承担整页内容。
5. 在对应页的 `notes` 中简要记录“AI 生成示意图”、用途和资源名。图片在现有转换报告中记为 `rasterized`；这表示图片媒体对象，周围原生内容仍可编辑。
6. 沿用现有预览和严格构建，确认资源加载、裁切和叠放正常。生图失败或资源不可用时，选择已有素材或原生表达并同步源稿，不保留只有 `prompt` 的占位来构建最终 PPTX。用户明确要求必须生成图片而当前无法完成时，说明这一限制。

后续修改时优先复用已经生成且适用的图片；只有主题、构图或素材要求变化时才重新生成。
