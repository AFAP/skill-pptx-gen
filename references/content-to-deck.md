# 长文档 → 多页 Deck

仅在输入是研究报告、长文章、多章节方案或会议材料时读取。本流程先压缩内容结构，再生成语义 deck，避免把原文逐段搬进页面。

## 先做页面计划

先抽取四类信息：

1. **任务**：受众是谁，演示要支持什么判断或行动。
2. **结论**：全文最重要的 3–5 个判断，按因果或决策顺序排列。
3. **证据**：支撑每个判断的数字、比较、案例和来源。
4. **边界**：不确定性、风险、口径差异和不能省略的限定条件。

然后为每页写一个紧凑计划，不写坐标：

```json
{
  "role": "evidence",
  "claim": "盈利改善主要来自毛利率和费用率修复",
  "evidence": ["毛利率 +4.2pct", "销售费用 -6.5%"],
  "visual": "chart-insight",
  "source": "2026H1 半年报"
}
```

一页只承担一个主要结论。多个结论共享同一证据时，优先合并证据，不重复整段原文。

## 页数估算

页数由“需要讲清的判断和证据组”决定，不按字数机械换算。以下只是起点：

| 输入规模 | 常见交付 | 建议起始页数 |
| --- | --- | --- |
| 短备忘录、单一主题 | 简报 | 5–8 页 |
| 多章节方案、常规报告 | 标准汇报 | 8–14 页 |
| 长篇研究、深度报告 | 摘要汇报 | 12–20 页 |
| 需要保留方法、附录和完整证据 | 详细汇报 | 20–30 页 |

33KB 左右的研究报告通常先做 12–18 页摘要版；若用户要求完整复现，再增加方法和附录页。封面、目录和结尾不应挤占核心证据页预算。

## 内容密度红线

- 每页 1 个主要结论、2–4 个关键证据；并列要点最多 6 个。
- 正文通常不超过 120 个中文字符；标题表达结论，不只写主题名。
- 同一段话无法在 18px 左右正文中自然容纳时，先删减或分页。
- 详细定义、引用和来源放 speaker notes；不要为了保留原文而缩小字号。
- 相邻页面避免连续使用三页同一种结构；数据、对比、过程和结论页要形成节奏。

## 选择表达形式

| 内容关系 | 优先表达 |
| --- | --- |
| 3 个以上可比较数字或时间序列 | 原生 chart |
| 构成、份额或业务组合 | bar / doughnut + 结论 |
| 两种方案、正反因素、现状与目标 | comparison |
| 时间、阶段或依赖顺序 | timeline |
| 同构指标或并列观点 | metrics / cards |
| 一张关键图片配解释 | split |
| 只有一句必须被记住的判断 | quote / section |

不要把可比较数据埋在长句里，也不要用手动画矩形代替原生图表。

## 推荐叙事顺序

常见研究汇报可按以下节奏裁剪，而非固定套用：

1. 封面与一句话结论。
2. 核心判断与主要风险。
3. 外部环境或问题规模。
4. 关键证据：业务、财务、用户或技术。
5. 解释机制：为什么发生、能否持续。
6. 情景、选择或行动建议。
7. 验证指标与结论。

每页的 `notes` 或 `speakerNotes` 应保留来源；需要机器可识别时使用：

```text
[Sources]
- 来源名称：URL 或文件名
[/Sources]
```

## 低 token 做法

- 先保存页面计划，再从计划生成 deck；不要在每页重复整份原文上下文。
- 能用语义版式表达时不写 primitive 坐标。
- 相同页脚、主题和配色放顶层，不在每页重复。
- 图表只保留展示所需数据；完整数据和推导放来源或附录。
- 完成后回查原文，确认关键限定条件、单位、日期和数据口径没有被压缩掉。
